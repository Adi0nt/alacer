# Session 32 diagnostic protocol v1

Recorded before testing. Exploratory only; original aa31 / aa31w2 protocols and verdicts remain immutable.

Four fresh terrain launches, monitor on/off/off/on, no retries; stop early on a clear explanation, failed functional checks, or 30 minutes wall clock from diagnostic series start (including quiet waits). Do not start a launch with less than seven minutes left. Each retains the complete Session 31 terrain path, phase lengths, Java 25, 2G heap, display lists, 1920x1080, P-core affinity and fixed High performance plan. Quiet wait is capped at 60 seconds. Original 5%/3% and CPU limits unchanged; these observations establish no calibration, significance or detection power.

Existing in-client frame CSV/sections, reference client/process CPU and chunk/processor data remain enabled in all launches and supply independent timing when the environmental monitor is off. The independent Windows .NET thread sampler polls once per second in all launches: per-thread user/kernel CPU, start address/module, cumulative process CPU, own CPU/wall overhead. Attach Java default JFR once client identity is verified, before reference phases; record compilation, GC, sampled stacks and Java thread CPU from supported default events. Two jcmd Thread.print snapshots near elapsed 45 and 280 seconds map Java native thread ids and stacks; their intervals are attribution-only and retained, never silently removed. JFR and sampler overhead cannot be separated by this experiment. No driver configuration is changed. No elevated ETW capture is assumed available.

Interpretation is descriptive: compare per-phase and 5-second frame/section trajectories, CPU moved off the client, top native/Java thread CPU, compiler/GC and environmental records. Native start module is a thread origin, not a sampled call stack or proof of current execution in that module. Contradictory/failed launches stay visible. Monitoring-off launches cannot pass environmental acceptance. Four launches are insufficient for a 2% overhead or improvement claim. No new warmup is adopted from correlation alone.

Record original power plan and restore in finally. Use the existing one-time foreground helper; never reclaim focus during a phase. Preserve raw outputs under run/alacer/stability/diag32, frames under run/alacer/benchmarks, logs under build, compact records in this archive. Hash original tracked archives plus every raw file listed in aa31w2 records before and after, and retain the comparison. No build/test workloads during measurements. No automatic extension, full pilot or next session.
